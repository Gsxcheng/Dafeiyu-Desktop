# 产品需求文档 PRD｜大肥鱼 Desktop（Dafeiyu Desktop）

- 文档状态：**DRAFT，待产品负责人审核**
- 版本：0.1（需求草案）
- 日期：2026-11-04
- 产品：大肥鱼 Desktop（项目名称已确定，开源跨端 AI 情感陪伴与智能体平台方向）
- 首个示范角色：大肥鱼（仅作为原型角色，不绑定平台架构）

## 1. 问题和价值主张

单渠道机器人容易让角色人格、聊天记录、记忆与插件配置被平台绑定；用户从 QQ 转移到手机 App 后不能续聊，机器人、模型和插件需要分开配置，提醒的投递缺少验证。

**价值主张：** 一次创建角色，多个渠道对话；人格和记忆持续且可控；技能通过插件扩展；普通用户尽量通过图形界面完成安装与管理。

## 2. 用户画像

1. **普通陪伴用户**：挑选人格、私聊、查看历史与记忆、控制主动互动。
2. **群主/社群管理者**：为 QQ 或其他已支持渠道配置 AI 群友、提醒与权限。
3. **工作型用户**：授权私聊/工作群查询信息、设置待办与审批任务。
4. **角色创作者**：无需编程就能创建、分享人格卡。
5. **第三方插件开发者**：开发、测试和发布可扩展技能。
6. **自托管用户**：自行部署、备份、升级并掌控数据。

## 3. 已确认产品方向与未决技术

**用户确认的方向：**
- QQ、微信等消息平台 + Desktop、Web、未来手机 App；经账号绑定后与同一角色持续对话。
- 情感陪伴、人格广场、自然主动聊天、表情与多模态。
- 跨端持久记忆，但群聊、个人、工作数据严格隔离。
- 一次性/周期提醒、待办、总结与工作 Agent。
- **工作 Agent 入口仅管理员私聊 + 指定工作群**。
- 开源社区插件，网友能自定义、发布和安装功能。
- 集中式 Desktop 管理，海蓝色与鲸鱼娘风格，长期支持桌宠。

**不作为技术定案：** SnowLuma、NapCat、AstrBot、DeepSeek Harness 均为候选；Tauri/Electron、SQLite/远端数据库、托管形态和个人微信接入尚待验证。

## 4. 功能需求

### F-01 人格与角色（Must 基础 / Should 广场）
- 一个账号拥有多个角色，每个角色具备稳定 ID、可版本化的角色卡。
- 角色卡覆盖背景、性格、表达方式、主动策略、记忆范围、技能与素材许可。
- 人格、模型、渠道和插件解耦，支持角色预览和导入导出。
- 公共角色卡不能突破平台权限或执行任意系统指令。

### F-02 对话与渠道（Must）
- 统一消息事件：channel、external_message_id、external_user_id、conversation_id、character_id、content_parts、timestamp。
- 收发去重、来源追踪、发送状态、失败原因、平台差异降级。
- QQ 是第一个验证渠道；其他渠道采用适配器。
- 同一角色不意味着不同群的对话上下文自动共享。
- 私聊跨端连续须通过经过验证的账号绑定和用户授权。

### F-03 情感互动（Must 基础 / Should 增强）
- 自然参与群聊，无需每次 @，同时避免刷屏与过度打扰。
- 主动聊天支持群白名单、免打扰时段、限频与紧急关闭。
- 原生表情、图片消息和看图/生图能力按渠道能力适配；语音作为后续能力。
- 不误导用户认为 AI 是有意识的人类；不以情绪操纵建立依赖。

### F-04 长期记忆（Must 最小版）
- 短期上下文、个人长期记忆、群记忆、工作引用分层。
- 用户可查看、纠正、删除、导出本人记忆；记录来源和授权范围。
- 私聊个人记忆跨端复用需主动授权；群空间默认隔离。
- 对他人传言、敏感信息、凭据不自动固化为可检索长期事实。
- V0.1 可从 SQLite 开始，是否使用向量检索以实测决定。

### F-05 提醒与待办（Must）
- 一次性提醒、周期提醒、目标用户和时区；创建后给出目标和时间。
- 待办包括创建者、负责人、所属空间、截止时间、状态及操作历史。
- 触发器和消息投递分离，重启恢复，幂等、有限重试和失败可观察。
- 模型文字说“已设好”不能取代真实数据库记录与投递结果。

### F-06 工作 Agent 权限（Must）
- 调用入口为管理员私聊与配置白名单的工作群，普通娱乐群禁止访问工作资料。
- 按角色、群、用户、工具四维后端授权，群里的普通成员不能自动继承管理员权限。
- 第一版工作工具只读；修改配置、重启、部署和写入须另行审批。
- MCP/API 最小权限、超时、审计；密钥不写日志、不回显给模型或插件。

### F-07 插件生态（Must 兼容验证 / Should 市场）
- 发现、安装、配置、启停、更新、回滚、故障诊断和版本管理。
- 先验证现有 AstrBot 插件 SDK 与社区插件市场；写一个最小测试插件。
- 后续提供 SDK、示例、插件广场、兼容矩阵、作者与版本信息、举报和审查。
- 第三方代码默认不可信，UI 的“权限声明”不等于操作系统级沙箱。

### F-08 Desktop / Web / App（Must 架构预留 / Should 产品化）
- Desktop 集中管理机器人、渠道、模型、人格、记忆、插件、提醒、任务、日志与诊断。
- 后续提供单窗口安装向导、托盘常驻、自动升级、备份和恢复。
- Web/手机 App 复用统一账号和角色服务，支持历史同步与推送。
- 核心数据不得只保存在某个 QQ 适配器或 Desktop 的独有内部格式。

### F-09 人格和插件广场（Should）
- 人格广场包含角色卡发布、搜索、预览、收藏、导入、作者与许可。
- 插件广场包含开发者、版本、依赖、权限、兼容性、反馈、审核与风险提示。
- 上架不等于官方安全背书。

### F-10 品牌、UI 和桌宠（Should / Could）
- 仓库名 `Dafeiyu-Desktop`、Desktop 产品名「大肥鱼 Desktop」已确定。
- 海蓝、清透、聊天优先，鲸鱼娘为示范形象；详见根目录 `DESIGN.md`。
- 角色头像、立绘、表情、Q 版桌宠素材需原创或有合法授权。
- 后续桌宠采用独立透明小窗，与主程序共享身份、人格、记忆和任务。
- 屏幕、麦克风和摄像头权限默认关闭，须单独授权。

## 5. 非功能需求

- **可靠性：** 消息去重、任务恢复、真实投递状态、故障日志和审计。
- **隐私：** 身份验证后绑定、跨群隔离、用户可导出/删除记忆。
- **安全：** 外部输入不可信、工具后端鉴权、插件分级隔离、秘密不入 Git。
- **可观察性：** request_id 串联收信、LLM、工具与发送，日志默认脱敏。
- **易用性：** 后期普通用户无需命令行即可安装、挑角色、配模型、聊天。
- **可替换性：** 角色、记忆和任务模型独立于底层聊天机器人框架。

## 6. V0.1 不做

不自研全套 Agent 框架、不部署线上人格广场、不发布手机 App、不承诺个人微信稳定接入或 QQ 非官方接入免风控、不允许普通群成员执行高权限工具、不静默更新未知第三方插件。

## 7. 成功标准

10 轮真实聊天收发没有重复回复；提醒实际触发可查、可取消；待办和记忆重启后存在；记忆可以删除；群越权读取和工具调用由后端拒绝；第三方测试插件可启停；日志无真实秘密。
